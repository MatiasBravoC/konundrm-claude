# Evidence: T31 — `run_slices.py` runs one headless session per slice until the feature is done, a session is blocked, waits for a decision or fails

Covers R1.4 · Threats row 3 of `design.md` (`run_slices.py` → headless sessions).

## What changed during the task

The first code and security reviews found three Critical problems, each CONFIRMED by a
finding-verifier that reproduced it with a fake `claude`:

- A. A `BLOCKED:` line decorated the way the stop gate accepts (`**BLOCKED:** …`, `> BLOCKED: …`,
  `- BLOCKED: …`, indented) did not stop the run: 2 sessions, `DONE`, exit 0.
- B. The runner never read `Checkpoints:`: on a plan with `Checkpoints: ask` (or no such line) it
  chained the next slice with no person approving the pause: 2 sessions, `DONE`, exit 0.
- C. A session waiting for a decision (`RED: T<n> waits for a decision`, `Decisions: ask`) did
  not stop the run either.

A and B were fixed within the plan: the stop-line rule moved out of `quality_gate.py` into
`deliberate_stops.py`, shared by the stop gate and the runner, and `tasks_document` now reads
`Checkpoints:`; the runner refuses before any session, exit 2, unless the plan is readable,
`Approved` and `Checkpoints: pre-approved`, and opens none for a plan already `Done`. C needed a
plan change: on 2026-11-01 the user chose "Detener ante RED:", so R1.4 names a fourth ending (a
session waiting for a person's decision) and design.md's last line gains `RED: <línea>`.

slice S1 with T1 and slice S2 with T2), changed per scenario where noted. The fake `claude` is a
Python script behind a `claude.cmd` wrapper (Windows cannot start a shebang script). Per call, it

## Invariant (property test)

`test_run_slices.py::RunSlicesTest::test_claude_gets_only_the_resume_prompt_and_the_arguments_after_the_separator`:
10 seeds, 0–5 arguments after `--` drawn mostly from `--`, `-p`, `--print`, `--claude`,
`--max-sessions`, `--permission-mode`, `acceptEdits`, `--dangerously-skip-permissions`, an empty
string and a token with a space (plus `& | ^ % " < > !` on POSIX); each seed ends `DONE` (2
sessions) or `FAILED` (1 session). Every session's arguments equal `-p`, the resume prompt and
exactly those arguments, in order.

## Mutation testing

`mutmut` needs `fork()` and does not run on native Windows; this repository's CI has no mutation
job, so the task's mutation command is replaced by hand mutants. A throwaway script
(`mutate_run_slices.py`, kept in the session notes folder as `s9-tools/mutate_run_slices.py`)
copies `plugins/konundrm-eng/hooks` and `skills` outside the repository, applies one textual
change at a time to `run_slices.py` or `deliberate_stops.py`, and runs `tests.test_run_slices`,
`tests.test_quality_gate`, `tests.test_tasks_document` and `tests.test_deliberate_stops`; the
unmutated copy passes. 38 mutants: the argv (arguments after `--` dropped, a permission flag
added, `-p` dropped, the feature dropped from the prompt, split at the last `--`), the stops
(failures ignored, negative exit codes as success, stop lines ignored, the last stop line kept,
a stop line checked before a failure, RED not a stop, no decoration allowed, closing decoration
kept, lowercase accepted, not multiline, every stop reported as BLOCKED, the reason running past
its line), DONE (exit 1 before or in the loop, never DONE, no check before the loop), the refusal
(no check, unreadable plan, any Status, any Checkpoints, exit 0, no message), the exit codes, the
session's stdin, UTF-8 decoding and output, the echo of each session's output, and `claude`
missing or unstartable (exit 0, no message, an exception).

- First run, after the fix round: 24 killed, 14 survived.
- The 14 went to a test-writer (surviving-mutant prompt), which added
  `test_echoes_each_sessions_output_as_utf8_before_the_first_stop_line`,
  `test_a_session_gets_an_empty_stdin`, `test_a_session_killed_by_a_signal_fails_the_run`
  (POSIX only), `test_says_claude_cannot_be_found_or_started`, a "blocked and failed" scenario,
  a sharper check of the unreadable-plan refusal, and `test_deliberate_stops.py`.
- Final run: 37 of 38 killed. The survivor is "negative exit codes count as success"
  (`run_slices.py:154`, `!= 0` → `> 0`): its test kills a session with SIGKILL and is skipped on
  Windows, which has no negative exit codes; CI runs the tests on ubuntu and macos too.
