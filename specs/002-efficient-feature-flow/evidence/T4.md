# Evidence: T4 — the commit gate and the dependency guard get the event intact, and the gate still fails closed

Covers R5.4 · Threats row 1 of `design.md` (`run.sh` → commit gate and guard).

## End-to-end run of the real gate through `run.sh`

A throwaway script in the session scratchpad (`t4-e2e.sh`) creates a Git repository outside the
project with one staged file, then sends the real commit gate, through the launcher, the PreToolUse
event Claude Code sends for `git commit -m "add a"`. Nothing in the hook path is faked: the event
goes through `sh plugins/konundrm-eng/hooks/run.sh gate_git_commit.py`, which starts the real
`gate_git_commit.py`, which runs the check. The check itself is a one-line red or green command set
through `KONUNDRM_CHECK_CMD`. Run on Windows 11 (Git Bash), 2026-10-30.

Command, from the repository root:

```
sh "$SCRATCHPAD/t4-e2e.sh" plugins/konundrm-eng/hooks/run.sh "$SCRATCHPAD/t4-e2e-work"
```

Output (verbatim, except the script's last line, `python used: <path>`, left out because it shows
the home folder; the script prints each command with the repository and data folders elided):

```
== 1. Red check: the gate, through run.sh, must deny the commit
$ printf '%s' "$event" | CLAUDE_PROJECT_DIR=<repo> CLAUDE_PLUGIN_DATA=<data> KONUNDRM_CHECK_CMD='python -c "print('1 failed'); raise SystemExit(1)"' sh run.sh gate_git_commit.py
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "Quality gate failed: `python -c \"print('1 failed'); raise SystemExit(1)\"` exited 1. Commit only on green (Standards → Definition of Done). Fix the failures, then commit again.\n\n1 failed"}}exit=0

== 2. Green check, for contrast: the gate lets the same commit through
$ printf '%s' "$event" | CLAUDE_PROJECT_DIR=<repo> CLAUDE_PLUGIN_DATA=<data> KONUNDRM_CHECK_CMD='python -c "raise SystemExit(0)"' sh run.sh gate_git_commit.py
exit=0 (no output means the commit is allowed)

== 3. No Python on PATH: run.sh itself still denies the commit (fails closed)
$ printf '%s' "$event" | PATH=<empty dir> CLAUDE_PLUGIN_DATA=<data> sh run.sh gate_git_commit.py
{"hookSpecificOutput": {"hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "konundrm-eng: no Python 3.10+ found, so the commit gate cannot check this commit. Install Python (python3, python or py on PATH) and restart Claude Code, or commit outside Claude Code."}}
exit=0
```

What the transcript does not show: before each case the script empties the data folder
(`CLAUDE_PLUGIN_DATA`), so case 3 cannot reuse the interpreter path case 1 cached there (a cached
absolute path would still resolve with an empty `PATH`), and it sets `CLAUDE_PROJECT_DIR` to the
throwaway repository in every case. In case 2, no output means the gate does not object; Claude
Code's own permission flow still applies to the command.

The event the script sends (the repository path elided):

```
{"session_id":"t4-e2e","cwd":"<repo>","hook_event_name":"PreToolUse","tool_name":"Bash","tool_input":{"command":"git commit -m \"add a\"","description":"Commit a"}}
```

## Mutation testing

There is no mutation tool for `sh` (mutmut mutates Python), as the task's `Mutation` line says. The
per-script cases of the task's test, and the invariant's property test, replace it. Mutants of
`run.sh` were built by hand in scratch copies outside the repository (the real file was never
edited), and the tests were run against each copy:

| Mutant of `run.sh` | Built by | Result |
| --- | --- | --- |
| Fast path taken for every script (`if true`) | test-writer, security reviewer | killed: the gate and the guard never start Python |
| Every script reads the first 8 KB, only the recorder gets it back | test-writer | killed: Python got 19,021 of 27,213 bytes |
| The 8 KB `dd` read moved ahead of the branch, for every script | security reviewer | killed: the gate and the guard get a truncated event |
| The no-Python gate's `*git*commit*` match removed | security reviewer | killed: the deny assertion errors |
| A case-insensitive `*record_*` match instead of the exact name | property test-writer | killed by the property test |
| Every script reads the first 8 KB (`dd`/`cat` by absolute path), Python gets it replayed, and the no-Python gate matches only that start | security re-review | survived the first two tests; killed by `test_without_python_the_gate_denies_a_commit_past_the_first_8_kb` (an event whose only `git commit` lies past byte 8192 is allowed under the mutant, denied by the real `run.sh`) |

Tests that killed them:

- `plugins/konundrm-eng/hooks/tests/integration/test_hook_scripts.py::HookScriptsTest::test_run_sh_passes_the_event_intact_to_the_gate_and_the_guard`
  (both scripts, `ls` and `git commit -m x`, small and ~27 KB events compared byte for byte; the
  no-Python deny).
- `plugins/konundrm-eng/hooks/tests/integration/test_hook_scripts.py::RunShFastPathPropertyTest::test_run_sh_hands_every_other_script_its_event_untouched`
  (the invariant: every script `hooks.json` runs through `run.sh` other than the recorder, the
  skills' scripts and eight near-misses of the recorder's name get the event byte for byte).
- `plugins/konundrm-eng/hooks/tests/integration/test_hook_scripts.py::HookScriptsTest::test_without_python_the_gate_denies_a_commit_past_the_first_8_kb`
  (without Python, the launcher's own fallback reads the whole event, so a commit past the first
  8 KB is still denied). The orchestrator reran it against the mutant's scratch copy: 2 of 2 runs
  failed; on the real `run.sh` it passed 5 runs in a row.

Surviving mutants, from the security re-review's runs against scratch copies:

- **Fast path also taken for `session_doctor.py`, `quality_check.py`, `improvement_notes.py`, or
  the near-misses `[Rr]ecord_check_result.py` and `record_check_result`:** no test kills them. The
  property test draws one event per name, and for these five names the drawn event is one the fast
  path sends to Python anyway (the check command, or a command past byte 8192). Equivalent in real
  use: SessionStart events and the skills' calls carry no `tool_input.command`, so the fast path
  would hand them to Python whole; the near-misses are not scripts, or, on a case-insensitive
  filesystem such as Windows', `Record_check_result.py` opens the recorder itself, for which the
  fast path is the intended behavior. The gate and the guard,
  the scripts row 1 protects, are killed by both tests.

The security reviewer also ran the gate and guard cases under `dash` (WSL, an LF copy of `run.sh`):
both scripts got identical bytes for small events, events over 8 KB with multibyte text, and an
event with CRLF and trailing blank lines; without Python the gate denied `git commit` (an event over
8 KB) and allowed `ls`. macOS (`bash` 3.2) was not run locally; CI runs these tests on
macos-latest.
