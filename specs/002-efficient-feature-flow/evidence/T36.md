# Evidence: T36 — `session_costs.py` never prints message, command or result content

Covers R6.3 · Threats row 4 of `design.md` (transcripts → report). Run on Windows 11 (Git Bash),
Python 3.13, 2026-11-01. No transcript text is copied here: only counts, the report's own output
(role names and numbers) and its error lines (a path and an error type). `<scratchpad>` stands for
the session's scratchpad folder.

## What changed

With well-formed transcripts the report already printed only role names and numbers. The leak was
on the error path: `_parse_timestamp` raised `datetime.fromisoformat`'s `ValueError`, whose message
repeats the timestamp text, and the uncaught exception printed it with a traceback on stderr (the
task's test planted an email, a key with a real shape and code in a timestamp, and all ten planted
fragments reached stderr). Decision recorded in `tasks.md` (Option A, recommended): `main()` catches
any error raised while reading a transcript or its subagent's `meta.json` and writes one line,
`session_costs: cannot read <path>: <error type>`, never the error's message nor a traceback,
prints nothing on stdout and exits 1.

## Data: the 0.6.0 run's transcripts

The five project folders of the 0.6.0 run (one scratch workspace and four worktrees, one session
each) were copied to `<scratchpad>/v6/{a,b,c,d,e}`, with each session folder's id cut to its first
8 characters: their original paths reach 311 characters, past Windows' 260-character limit, which
T38 handles. The report reads 478 transcripts from them (5 sessions, 473 subagents).

Preparing this evidence found that `read_transcript` splits a file with `str.splitlines()`, which
also breaks at U+2028, U+2029 and U+0085; JSON allows those characters raw inside strings, and 31
valid lines of 9 of these transcripts hold them (41 lines in 15 of the 1,332 transcripts on this
machine). The split pieces are not JSON, so the report stops at the first one. That belongs to T37
(which lines are invalid). For a full run, a second copy, `<scratchpad>/v6e`, writes those
characters as JSON escapes (`\u2028`, `\u2029`, `\u0085`) in the 31 lines; the script that made it
checked that every rewritten line parses to the same value.

## Method

`t36_evidence.py` (a throwaway script in the scratchpad, kept in the session notes folder as
`s11-tools/t36_evidence.py`) collects distinct 32-character fragments (the first line of a text
with at least 32 characters and 8 letters) from where content lives: user messages (string and
text blocks), assistant text and thinking, shell commands, other tool inputs (Write, Edit, Agent
prompts…), tool results, the top-level `toolUseResult` stdout and stderr, other line types'
message text and every `meta.json` description. It samples up to 150 per category with a fixed
seed, runs `sh plugins/konundrm-eng/hooks/run.sh session_costs.py <folders>` from the repository
root, counts the fragments found on stdout and on stderr, and sorts every stdout line by shape
(header, role row, numbers, blank, title).

## Invariant

`test_every_output_line_is_a_fixed_header_a_role_or_numbers` checks the task's invariant over 24
seeded examples of generated well-formed transcripts (one or two folders, sessions and subagents,
arbitrary text with look-alikes of rows, headers, numbers, role names and "Traceback" in every
place content lives): every stdout line is blank, a fixed header or title, a role row of numbers,
or the busiest block's numbers, and stderr is empty. It passed on the code before the change too,
since well-formed transcripts never leaked.

## Mutation

`mutmut run --paths-to-mutate plugins/konundrm-eng/hooks/scripts/session_costs.py` does not run on
native Windows; the `risk:high` CI run repeats mutation testing on Linux. Hand mutation instead
(`mutate_session_costs.py`, kept as `s11-tools/mutate_session_costs.py`): each mutant is one
textual change to the script in a copy of the hooks folder outside the repository, run against
`test_session_costs` (about 3 s per mutant); the unmutated copy passes first.

First run, on the GREEN code: 14 mutants, 8 killed, 6 survived (M4, M5, M6, M7, M13 and M10).
A test-writer added `test_unreadable_transcript_exits_1_with_one_line_naming_file_and_error_type`
(a directory named like a session transcript, an error that stays one after T37 skips invalid
lines; the expected error type is read from the platform, PermissionError on Windows and
IsADirectoryError on Linux) and `test_unusable_meta_json_prints_no_traceback_and_none_of_its_text`
(a meta.json without `agentType` and one that is not JSON, both holding planted text). Second
run: 14 of 14 killed.
