# Slice S7 summary: a task's commit reuses the green check, carries its rounds and resumes from `status`

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T24–T26

## What changed and why

develop-feature's gate (Phase 3 step 6) now starts with `task_ledger.py status` and runs the check
only when `status` does not show it green for the current tree, so the implementer's last check
stands when nothing changed after it; a red check's fix goes back through the verify command, the
reviews and verify by risk before the gate repeats (T24, R2.5, R2.6, R4.7). A task's commit is one
command line, `msg=$(… task_ledger.py message … --rounds …) && git add -A && git commit -F "$msg"`,
with the session's co-author as `--trailer`: its review rounds travel in the message, the commit
leaves the plan's box and Rounds line alone, and the plain `git commit` goes through the commit gate
like any other commit; committing-changes' develop-feature mode says the same, with a quoting rule
that lets the shell expand nothing, and its fix-bug mode now states its own steps (T25, R2.7, R4.2,
R4.3). Resuming runs `status`, which counts only `Task:` commits in `<base>..HEAD`, instead of an
unranged `git log` search that also found feature 001's commits on main (T26, R1.8, R4.7). Together
they remove the second full check each task ran in S3–S6: T25 and T26 were committed this way, in
2.7 s and 3.5 s with the hooks included, the gate reusing the implementer's check.

## Risks and high-risk tasks

- **Risk per task:** T24 low, T25 high, T26 low.
- **High-risk tasks:** T25. Mutation: none (`Mutation: no aplica a prosa; la evidencia lo
  reemplaza`). Evidence in `specs/002-efficient-feature-flow/evidence/T25.md`: the real commit gate,
  reached through `run.sh` in a throwaway repository, denies the commit line on a red check (the
  check ran: 1 → 2 runs), lets it through without a second check when the implementer's green check
  covers the tree (1 → 1 run), and denies the same line from a subagent; the commit carries
  `Task:`, `Rounds:` and `Co-Authored-By:` as Git trailers and leaves the plan's box open. The
  invariant's property test shows `message` changes no file of the repository, `.git` included,
  but its message file, for 16 inputs with shell metacharacters. One Critical finding (the
  single-quote rule), CONFIRMED by a finding verifier, was fixed in one fix round; the security
  re-review passed.
- **Open risks:**
  - `## Parallel partitions` step 4 still checks a partition branch with
    `git log -E --grep '^Task: T<n>( |$)' <branch>`, which has no base range, so it would also find
    an earlier feature's `Task:` commits on main; Phase 0's wave bullet no longer says how to spot a
    task committed only on its partition's branch. Outside T26's files.
  - `task_commits` reads `Task:` and `Rounds:` from any line of a commit message: a `--body` line
    that starts with `Task: T<n>` would mark that task as built (security review Suggestion;
    hardening, since only the orchestrator writes the body).
  - The gate's parser does not see a command inside backticks or `$(…)` within a quoted word. The
    quoting rule closes that path for a task's commit only; the hand-written commits of this mode
    (slice summary, partition report, integration fix) and ordinary commits get no such rule.
  - The Slice checkpoint does not run `task_ledger.py close-slice` until S8's T27, while task commits
    already leave the boxes open: this session ran `close-slice S7` by hand for this summary, and the
    session that builds S8 loads the text before T27, so it must do the same at its own pause.
  - The contract tests match keywords per sentence, not meaning (the plan's convention). Known
    gaps: the unconditional-check sweep exempts any sentence that mentions `status`, `green` or
    `otherwise` (T24); a quoted heredoc anywhere in the subsection exempts every single-quote
    sentence (T25); the unranged-lookup guard misses `--grep=` forms (T26).

## Decisions

- Whether a red check at the gate sends the task through step 5 (verify by risk) again (T24, an
  open risk of T22): not said | step 5 again → **step 5 again** (orchestrator), so a fix at the
  gate cannot leave a high task's mutation run and end-to-end evidence stale.
- How the subject and body are quoted in the commit line (T25, after the security review): single
  quotes allowed as they were | a quoted heredoc | double quotes without `` ` ``, `$`, `"` or `\`,
  or single quotes without `'` → **the last** (orchestrator): it closes the confirmed path and
  keeps the commit a one-line command the gate parses.
- Where develop-feature's other commits get their `Task:` line (T25): through `message` | written
  by hand → **by hand** (implementer), since `message` refuses a task that already has its commit
  (slice summary, partition report, integration fix).
- Whether resuming still unchecks a box with no commit (T26): keep | drop → **drop** (orchestrator):
  `status` and the session doctor decide by commits, so resuming no longer edits the plan.
- When to run T25's end-to-end evidence: step 5, after the reviews | before the reviews →
  **before** (orchestrator), so the security review saw it and the evidence needed no re-review.
- How S7's own tasks were committed: as the loaded flow said (box and Rounds line in tasks.md) |
  the new flow once T25 landed → **T24 the old way, T25 and T26 the new way** (orchestrator), and
  this summary's commit carries `close-slice S7` (T27's behavior, ahead of S8).
- No subagent returned `Status: DECISION`.
