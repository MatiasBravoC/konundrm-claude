# Slice S4 summary: the task commit's message, the pause's bookkeeping and a session start by commits

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T11–T15

## What changed and why

S4 adds the task ledger's two other subcommands and moves the session start to commits.
`task_ledger.py message` writes a task's commit message (the subject, an optional body, then the
`Task: T<n> · Covers: …` and `Rounds: …` lines as Git's trailer block) under the Git directory and
prints its path, so one shell call can commit a task with `git commit -F` without touching
tasks.md (T11, R4.2, R2.7); it refuses, with exit 1 and nothing written, a task the plan lacks or
one already committed after the base (T12, R4.4). `close-slice` does the pause's bookkeeping in
one call: it checks the boxes of the slice's committed tasks and writes their rounds from their
commits, giving back every other byte with its own line ending (T13, R2.8, R4.5). The session
start now counts a task as done by its commit, whatever its box says, and falls back to the boxes
for a plan without a usable base (T14, R1.9); the impact report reads rounds written by
`close-slice` like those written per task (T15, R2.9). Plan IDs and commit keys now compare
through one function, `task_commits.task_key`, which also fixes `status` for zero-padded plans
(S3's open risk). The flow does not call `message` or `close-slice` yet: S7 commits each task
through `message` (T25) and S8 runs `close-slice` at the pause (T27).

## Risks and high-risk tasks

- **Risk per task:** T11 low, T12 low, T13 medium, T14 low, T15 low.
- **High-risk tasks:** none. T13 (medium) has a property test for both invariants. Hand mutants
  of `close_slice`, run in a copy of the hooks folder against T13's two tests (not required at
  medium risk): 10 of 12 killed. Survivors: the `not committed` list in reverse order (the
  behavior test has a single uncommitted task) and replacing the last instead of the first Rounds
  line of a block that has two (no real plan has two).
- **Open risks:**
  - On Linux under a C locale, `message` relies on `errors="surrogateescape"` to write the `·` of
    `--rounds` back as UTF-8. This machine runs Windows, so only the Linux CI run checks it.
  - `message` copies `--rounds` as given: a value not in the `spec <n> · code <n> · escalations
    <n>` form gives a commit that task_commits reads with no rounds, without any warning.
  - `close-slice` and tasks_document find a task's Rounds line differently: tasks_document takes the
    first match anywhere up to the next task, `close-slice` only a `- Rounds:` line inside the
    task's contiguous indented block. A `  * Rounds:` bullet, or a blank line inside a block before
    its Rounds line, would leave the old line in place, and `status` and the report would read it.
    The flow only ever writes `  - Rounds:` lines.
  - `close-slice` rewrites tasks.md in place, without a temporary file and a rename; an interrupted
    write could leave it truncated (Git still holds the committed version).
  - `status` answered in 0.55 s on this 42-task plan (S3); the 100-task bound of the constraints is
    measured in the Phase 4 diagnosis.

## Decisions

- No subagent returned `Status: DECISION`. These choices were made inside the tasks:
- The message's layout (T11): Task and Rounds lines anywhere in the body | as its last paragraph,
  Git's trailer block → **the trailer block** (orchestrator in the red step), so a later
  `git commit --trailer "Co-Authored-By: …"` appends to the same block.
- How `message` prints its path (T11): as Python prints | absolute, forward slashes, a bare LF →
  **a bare LF** (orchestrator in the red step, implementer), since Python's stdout writes CRLF on
  this machine (measured) and `msg=$(…)` keeps a trailing CR.
- Non-ASCII argv under a C locale on Linux (T11): rebuild the Rounds line from its numbers | write
  with `surrogateescape` → **`surrogateescape`** (implementer), which also keeps a non-ASCII
  subject or body.
- Finding a file under the Git directory (T11): a third copy of the `git rev-parse --git-path`
  lookup | one `working_tree.git_path` → **one function** (implementer's refactor; quality_check
  and `snapshot_tree` use it too).
- Zero-padded task IDs (T12): handle them in `message` only | one by-number key shared with
  `status` → **`task_commits.task_key`, shared** (orchestrator), which closes S3's open risk.
- `close-slice`'s report and refusal (T13): a `not committed: <ids | none>` line; an unknown slice
  is exit 1 → (orchestrator in the red step).
- A commit without a Rounds line (T13): drop the plan's Rounds line | keep it → **keep it**
  (orchestrator in the red step), since this feature's own commits through S4 carry no Rounds line.
- Tasks inside HTML comments (T13): writing-plans' template ends with a commented finished task;
  `close-slice` skips comments as the plan reader does (orchestrator added the case to the red).
- How the property test calls `close-slice` (T13): the CLI per seed | `close_slice(root, plan,
  slice)` in-process → **in-process** (orchestrator), to keep the check fast.
- The session start's wording (T14): "tasks done" | "tasks committed", with today's "tasks
  checked" line when it falls back to the boxes → **committed, with the fallback** (orchestrator
  in the red step), so the line says what it counted.
- What the session doctor shares with task_ledger (T14): its private `_plan_and_task_commits` | a
  small helper of its own on task_commits' public functions → **its own helper** (implementer),
  since that helper turns a Git error into the CLI's exit 2 and the hook must never raise.
