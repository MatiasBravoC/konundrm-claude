# Slice S2 summary: task commits are found only after the plan's base, and a green check is remembered beside the repository

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T5–T7

## What changed and why

S2 builds the three pieces the task ledger of S3–S4 stands on, none of them used by the flow yet.
The plan reader now gives the plan's `Base commit` (only a hex SHA, since it is handed to git) and
each task's `Covers` IDs, read from the field that ends the task line (T5). A new module,
`task_commits.py`, finds each task's commit with one `git log` over `<base>..HEAD`, so the `Task:
T1`–`T79` commits that feature 001 left on `main` no longer count as this feature's tasks, and reads
each commit's `Rounds:` line (T6). A passing check, whether Claude ran it or the commit and stop
gates did, now also writes its tree to `.git/konundrm-eng-green` (resolved with `git rev-parse
--git-path`), where any shell can read it without `CLAUDE_PLUGIN_DATA` (T7). They answer the
groundwork of R1.8, R1.9, R4.1 and R4.2; the commands that meet those criteria come in S3, S4 and S7.

## Risks and high-risk tasks

- **Risk per task:** T5 low, T6 medium, T7 low.
- **High-risk tasks:** none.
- **T6 (medium, mutation not required):** 9 hand-made mutants of `task_commits.py`, run against
  T6's two tests in a copy of the hooks outside the repository: 7 killed. One survivor is
  equivalent: dropping `int()` changes nothing, because the pattern's `0*` already strips the
  padding. The other is not pinned by any test: dropping the `(?= |$)` lookahead would let
  `Task: T1x` count as T1. The lookahead follows develop-feature's own `^Task: T<n>( |$)` search.
- **Open risks:**
  - Found while gating this slice: the commit gate ran the whole check again when T5 and T6 were
    committed (113 s and 105 s), because the orchestrator ran its gate check wrapped
    (`(time npm run check) > log`). The recorder counts only the check command as given, on
    purpose, since a pipe or a redirect could hide a failing exit. Run bare before T7, the check
    was recorded, `.git/konundrm-eng-green` matched the tree, and the commit took 1.9 s. This bears
    on R2.5 (one check per task) and on the Phase 4 diagnosis: the gate step should say to run the
    check exactly as given.
  - `task_commits` runs `git log` without `--no-show-signature`. With `log.showSignature=true` and
    signed commits, a gpg line could be read as the SHA. Only `TaskCommit.sha` would be wrong: the
    task and its rounds still come from the message. Not reproduced.
  - A commit message kept with CRLF (`Task: T1\r`) does not count. `git commit` strips the `\r`,
    so only `--cleanup=verbatim`, `fast-import` or plumbing can leave one.
  - The impact report now shares the stricter pattern: a hand-written `Task:T3` without the space
    no longer counts as a task commit there.
  - A cached gate hit does not rewrite the green-tree file. If another check recorded a different
    tree in between, `status` (T8) will report the tree as not recorded and the check runs once
    more; it can never report a tree that did not pass.
  - The file is per worktree (`--git-path`), so parallel partitions do not share it.

## Decisions

- No subagent returned `Status: DECISION`. These choices were made inside the tasks:
- What counts as the base commit (T5): any text on the line | only a hex SHA → **only a hex SHA**,
  4 to 64 digits (orchestrator in the red step; the implementer chose the lengths), because callers
  hand it to git as a revision.
- Which commit is a task's commit when several name it (T6): the newest | the oldest → **the
  oldest** (orchestrator in the red step): develop-feature puts the slice's last task's `Task:`
  line on the slice summary commit and on a partition's report commit, and those must not hide the
  task commit's rounds.
- What a pass with an unknown snapshot does to the record (T7): keep the old tree | delete it →
  **delete it** (implementer), so the file never names a tree as current when it may not be.
- `find_duplicates.py`'s private copy of the Git runner (T6): keep it | use `working_tree.run_git`
  → **use `run_git`** (implementer; the spec review judged it in scope).
