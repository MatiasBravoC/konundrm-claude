# Slice S9 summary: `run_slices.py` chains headless sessions, one per slice, from a terminal

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T31–T32

## What changed and why

A person who pre-approved the pauses can now build a feature from a terminal with
`sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" run_slices.py specs/<NNN-slug> [--claude PATH] [--max-sessions N] [-- ARGS...]`:
it runs `claude -p "/konundrm-eng:develop-feature specs/<NNN-slug>" ARGS` once per slice, adding no
flag of its own (only `-p`, the resume prompt and what follows the first `--`), echoes each
session's output, and its last line says how the run ended: `DONE`, `BLOCKED: <reason>`,
`RED: <reason>` (a session waits for a person's decision), `FAILED: exit <n>`,
`STALLED: session <k> added no commit` or `STALLED: reached the cap of <n> sessions` (T31, R1.4;
T32, R1.5). Before the first session it refuses, opening none, unless the plan is readable,
`Approved`, `Checkpoints: pre-approved` and names a base commit in the repository; a plan already
`Done` opens no session. It never opens more sessions than pending slices plus one, and
`--max-sessions` can only lower that cap. The reviews of T31 found three ways a run could go on
without a person: a Markdown-decorated `BLOCKED:` line, a plan whose pauses were not pre-approved
and a `RED:` decision wait. The stop-line rule moved from the stop gate into
`deliberate_stops.py`, shared by both; `tasks_document` reads `Checkpoints:`; and, with the user's
approval of a plan change on 2026-11-01, R1.4 names the `RED:` ending. develop-feature's
pre-approved paragraph gains one line saying when to use the command.

## Risks and high-risk tasks

- **Risk per task:** T31 high, T32 medium.
- **High-risk tasks:** T31: `mutmut` needs `fork()` and does not run on native Windows, and this
  repository's CI has no mutation job, so 38 hand mutants of `run_slices.py` and
  `deliberate_stops.py` ran in a copy against their tests → first 24/38 killed; the 14 survivors
  went to a test-writer; final 37/38 killed. The survivor (`exit_code != 0` → `> 0`) is killed only
  by the POSIX-only signal test, which CI runs on ubuntu and macos. Evidence, with the end-to-end
  run through `run.sh` (8 scenarios with a fake `claude` in two-slice test repositories), in
  `specs/002-efficient-feature-flow/evidence/T31.md`.
- **Open risks:**
  - The startable check runs once, before the first session: a session that left the plan
    unreadable, not `Approved` or not pre-approved still gets the next session, until a stop, a
    no-commit session or the cap ends the run (T31's code and security re-reviews).
  - "Added a commit" is "HEAD's SHA changed": a session that resets HEAD or checks out another
    branch passes as progress; `git rev-list --count <before>..HEAD` would match R1.5's wording
    (T32's code review).
  - On Windows, `shutil.which("claude")` searches the current directory first in a plain terminal,
    so a `claude.cmd` committed at the repository root would run instead of claude (T31's security
    review; not Critical, the sessions already run the repository's own check).
  - `--output-format json` or `stream-json` after `--` hides every stop line from the runner (T31's
    security review).
  - `read_tasks` raises `ValueError` from `zip(strict=True)` on a `tasks.md` with no task lines; the
    runner then exits 1 with a traceback and opens no session (pre-existing, now reachable).
  - `1. BLOCKED:` and `+ BLOCKED:` are stop lines for neither the stop gate nor the runner (by
    design of the shared rule).
  - Untested: the refusals for a plan with no base SHA or a base not in the repository, and
    `--max-sessions` rejecting `0` or a non-integer (T32's spec and code reviews); `checkpoints` has
    no direct unit test in `test_tasks_document.py`; the "Status: Draft" refusal's stderr check
    also matches other reasons (T31's code re-review).
  - `count_pending_slices` repeats `task_ledger._plan_and_task_commits`' base handling, and its
    "not in this repository" wording also covers a missing Git (T32's code review).
  - Still open from S7 and S8: see `summaries/S8.md` (step 7 commits nothing before step 8's
    `git status`; Parallel partitions step 4 without a range; `Task:`/`Rounds:` lines read from a
    commit body; commands inside backticks within a quoted word).

## Decisions

- How the runner treats a session that waits for a person's decision (`RED: T<n> waits for a
  decision`, the security review's third Critical, CONFIRMED by a finding-verifier): stop on `RED:`
  as a fourth ending (a plan change to R1.4 and design.md) | refuse plans whose decisions are not
  pre-approved too (a plan change) | no plan change, an open risk → **stop on `RED:`** (user,
  2026-11-01).
- Where the stop-line rule lives: a second copy in `run_slices.py` | one module shared with the
  stop gate → **`deliberate_stops.py`, shared** (code review; implementer).
- The summary of a decorated stop line: the line as printed | the marker and reason without the
  decoration → **undecorated** (`**BLOCKED:** x` → `BLOCKED: x`) (orchestrator), so the last line
  always starts with a documented word.
- Exit codes: 0 `DONE`; 1 a stop, a failure, a stall or the cap; 2 a refusal or `claude` that cannot
  start (implementer; pinned by the tests after the code review's suggestion).
- A session that prints a stop line and exits non-zero: `FAILED` wins (implementer; pinned by the
  "blocked and failed" scenario).
- The session cap's line: `STALLED: reached the cap of <n> sessions`; `--max-sessions` only lowers
  the cap of pending slices plus one (orchestrator, from design.md's `--max-sessions N`).
- A plan with no base commit in the repository: refused before any session (implementer; recorded
  in design.md).
