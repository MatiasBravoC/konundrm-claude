# Slice S8 summary: the pause closes the slice and hands the feature to a new session

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T27–T30

## What changed and why

develop-feature's pause now does the plan's bookkeeping and ends the session's part of the feature.
Step 2 of the Slice checkpoint runs `task_ledger.py close-slice`, which checks the box and writes
the Rounds line of each of the slice's tasks from its `Task:` commit, and commits that `tasks.md`
change together with the summary as `docs(<scope>): summarize slice S<k>`, also with pre-approved
pauses; the plan template's comment no longer says the box is checked in the task's own commit,
false since T25 (T27, R2.8, R4.5). A new step 8 continues the feature in a new session once the
pause is over and another slice or Phase 4 is left: the desktop app's session tools open it in the
same folder with `/konundrm-eng:develop-feature specs/<NNN-slug>`, and otherwise the session ends
with the exact `claude "…"` command; Phase 0 sends a session whose `status` prints `next: none` to
Phase 4 (T28, R1.1–R1.3). Before handing off, uncommitted files listed by `git status --porcelain`
stop the pause with a `BLOCKED:` line naming them (T29, R1.6). The plan header line
`- **Sessions:** single`, recorded in Phase 2 from the request or the plan approval, or set at a
pause and committed alone, keeps the next slice in this session; a plan without the line reads as
`per-slice`, and the writing-plans template carries it (T30, R1.7). Each turn of a long session
rereads its whole context, so a session per slice keeps the cost of a turn from growing with the
feature; S9 is the first slice whose session is opened by the flow's own step 8.

## Risks and high-risk tasks

- **Risk per task:** T27 low, T28 low, T29 low, T30 low.
- **High-risk tasks:** none.
- **Open risks:**
  - Step 7 turns changes asked at the pause into new tasks or a plan change once the user approves
    them, but no step commits that `tasks.md`/`design.md` edit before step 8, whose
    `git status --porcelain` would then stop the hand-off with `BLOCKED:` naming it. The stop is the
    safe outcome (R1.6); a commit in step 7 would avoid it.
  - Step 8 states the `Sessions: single` exception and the switch at a pause before "First run
    `git status --porcelain`", so the dirty-tree stop and the open-session sentence are not scoped
    to `per-slice` in words; only "instead" tells a reader under `single` to skip them (T30's code
    review suggested ordering it: switch, `single` stays here, otherwise check and hand off).
  - Step 2 says a task `close-slice` names as not committed must be built first, but not that the
    summary is then written again and `close-slice` run again (T27's code review).
  - Phase 0's "(every task is built and every slice has its summary commit)" says more than `status`
    checks: it prints `next: none` once every task has its commit, and the bullet above it runs a
    missing checkpoint first (T28's code review).
  - The contract tests match keywords per sentence, not meaning (the plan's convention). Known
    gaps: T27's rule that ties `tasks.md` to the summary commit has no negation guard; T28's
    pause-done rule accepts the summary or the notes, not both.
  - Still open from S7: Parallel partitions step 4 looks a partition's tasks up with an unranged
    `git log --grep`; `task_commits` reads `Task:`/`Rounds:` lines from a commit body; the gate's
    parser does not see a command inside backticks or `$(…)` within a quoted word.

## Decisions

- Whether T27 also fixes the plan template's comment, which still said the box and Rounds line go
  in the task's own commit (stale since T25, contrary to R2.8): leave it for Phase 4's whole-feature
  review | fix it in T27 → **fix it in T27** (orchestrator), with the template added to T27's test
  and files.
- Where `close-slice` runs: a new step | inside step 2, right before the summary commit → **inside
  step 2** (implementer), so no step number other sentences cite moved.
- Where the hand-off goes: a new last step 8, worded like Parallel partitions step 2 (implementer,
  from the orchestrator's sketch). It also falls back to the command when the app refuses to open
  the session, which the spec review accepted as R1.3's intent.
- How the session after the last slice reaches Phase 4: Phase 0 sends `next: none` to Phase 4
  (orchestrator; the task's "Phase 4 handoff").
- How a switch to one session asked at a pause is kept: set the header line and commit it alone as
  `docs(<scope>): build <NNN-slug> in one session` with the slice's last task's `Task:` line
  (orchestrator's suggestion, implementer's text), so step 8's dirty-tree stop does not fire and
  the line never rides in the next task's commit.
- No subagent returned `Status: DECISION`.
