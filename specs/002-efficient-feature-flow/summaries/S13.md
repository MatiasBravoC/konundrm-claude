# Slice S13 summary: the measurement skips every line it cannot use, and the check runs as given

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T43–T44

## What changed and why

Phase 4 found two gaps, and the user approved one task for each (a plan change of 2026-11-01).
The whole-feature spec review showed that `session_costs.py` still stopped the whole report, with
exit 1, on a line with a malformed tool block or a time without a zone, against R6.4. It now treats
as invalid, and counts under `skipped lines`, a `tool_use` whose `name` or `id` is not text or whose
`input` is not an object, a `tool_result` whose `tool_use_id` is not text, and a timestamp without a
time zone, and the [0.7.0] changelog no longer lists them as a known limitation (T43). The measured
comparison of the 0.6.0 and the 0.7.0 on the same tasks showed that the agents ran the check with
its output trimmed (`npm run check 2>&1 | tail`), which the recorder ignores on purpose, so the gate
step and the commit ran it again, against R2.4 and R2.5; the implementer's check step and
develop-feature's baseline and gate now say to run the check command exactly as given, alone in its
own shell call, with no pipe, redirection or other command around it, so its pass is recorded and
the commit reuses it (T44). The hook suite went from 480 to 482 tests (1 skipped on Windows).

## Risks and high-risk tasks

- **Risk per task:** T43 low, T44 low.
- **High-risk tasks:** none.
- **Open risks:**
  - T44's rule says "with no pipe, redirection or other command around it", but the recorder also
    accepts a leading `cd <root> &&` and needs the call to start in the project's root; an agent
    that reads the rule literally and runs the check from another folder is not recorded. Saying
    "from the project root (a leading `cd <root> &&` is fine)" would close it (T44's code review).
  - T44's test: in the Phase 3 gate, its "why" rule already matches an older sentence ("a passing
    check recorded on exactly these files"), so dropping the new reason there would go unnoticed;
    the test as a whole still fails on the old text (T44's code review).
  - Two lines of `skills/develop-feature/SKILL.md` (102–103 and 246) pass the file's
    100-column wrap (T44's code review).
  - Still open for `session_costs.py` (the [0.7.0] Known limitations): a folder that does not
    exist gives an empty table with no warning; subagents that workflows start are not read; a
    user-given `--check-pattern` is searched anywhere in a command; the test-runner list is fixed.
  - T44's effect on the number of full checks per task is estimated in
    `evidence/diagnosis.md`, not measured: the user chose not to repeat the comparison.
