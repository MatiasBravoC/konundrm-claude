# Slice S1 summary: the hook that records checks no longer starts Python for a command that is not the check

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T1–T4, T42

## What changed and why

Every Bash or PowerShell command paid for a Python start in the PostToolUse hook that records a
passing check (`record_check_result.py`; 305 ms per command in the 0.6.0 run's transcripts), though
almost no command is the check (R5.1). `run.sh`, the launcher every hook goes through, now decides
first. For the recorder only, it reads the event's first 8 KB with one `dd` read and cuts
`tool_input.command`'s value at its first unescaped quote. When that value cannot hold the
project's check, it drains the rest of stdin and exits without starting Python. Commands with
quotes or backslashes are decided too: the check word is searched for in the escaped JSON text,
which spells it as the command does (T42). Anything it cannot read still goes to Python, which gets
the event byte for byte (R5.2, R5.3): a command past the first 8 KB or with no closing quote there,
a missing or non-string command, a `\u` escape in the value, any escape when the check word holds
`"`, `\` or `/`, a value that takes more than 64 steps to cut, or a `KONUNDRM_CHECK_CMD` holding a
character outside printable ASCII. Every other hook, the commit gate and the dependency guard
included, gets its stdin untouched, and without Python the launcher still denies commits (R5.4).

How it was built:
- T1 built the fast path (`run.sh`, +93 lines). T2–T4 were characterization tasks: their behavior
  already held, so their commits add only tests, plus T4's evidence.
- T42 was added after the first version of this summary (plan change `864892d`, approved by the
  user). That version said the fast path costs about 47% less, but not how many commands take it.
  Counted over the 0.6.0 run's 5,016 shell commands, T1's rule (any JSON escape sends the event to
  Python) let only 86 of them (1.7%) take it: almost every command carries double quotes, which
  JSON writes as `\"`, since the repository's path has a space. The other 98.3% paid about 100 ms
  more than in 0.6.0 for `dd`, `cat` and a pipe ahead of Python, so T1–T4 alone would have made
  that run about 8 minutes slower, not faster. T42 makes `run.sh` decide on the escaped text
  (`cut_json_string`, +48 lines).
- Defects caught before commit:
  - T1: the code review found that BSD/macOS `head -c 8192` can consume more of a pipe than it
    prints, so the reader became `dd bs=8192 count=1` (one `read(2)`).
  - T1: the invariant's property test found that an override padded with Unicode whitespace
    (U+00A0, U+2003, U+3000) made the fast path skip a real check. Any character outside printable
    ASCII in the override now sends every event to Python.
  - T42: the spec review twice found an invariant the tests did not pin. First, T1's property
    still discarded every quoted command. Then, after it was widened, no case reached the `\u`
    guard: its `\u00XX` cases fell on check words that the `" \ /` guard already sends to Python.
    Hand-made mutants confirmed the second gap before it was fixed.
- Each invariant has a seeded property test in `RunShFastPathPropertyTest`, which runs once per
  check (about 13 s for the five).

Measured on this machine (Windows 11, Git Bash), `sh run.sh record_check_result.py`, median of 20
runs per case after one warm-up, same method for the three launchers (ms):

| Launcher | `ls -la`, 2 KB | `cd "<root>" && git status --short`, 2 KB | `grep -rn "def main" "<root>"`, 200 KB | `cd "<root>" && npm run check`, 2 KB |
| --- | --- | --- | --- | --- |
| 0.6.0 (base commit) | 209 | 208 | 205 | 338 |
| T1–T4 | 106 | 310 | 342 | 464 |
| T1–T4 and T42 | 112 | 115 | 110 | 446 |

A command that takes the fast path costs about 46% less than in 0.6.0, quoted or not; one that goes
to Python costs about 100 ms more. Modelled over the 0.6.0 run's 5,016 shell commands (about 450
bytes before `tool_input`, check word `check`):

| Decision | T1–T4 | T1–T4 and T42 |
| --- | --- | --- |
| Fast path | 86 (1.7%) | 3,734 (74.4%) |
| Python: holds the check word (`git checkout` counts) | 17 (0.3%) | 1,002 (20.0%) |
| Python: a JSON escape | 4,896 (97.6%) | — |
| Python: more than 64 steps to cut the value | — | 204 (4.1%) |
| Python: a `\u` escape | — | 59 (1.2%) |
| Python: past the first 8 KB | 17 (0.3%) | 17 (0.3%) |

With those costs, that run would have spent about 4 minutes less on this hook with T42, against
about 8 minutes more with T1–T4 alone. The hook cost about 25 minutes in that run.

## Risks and high-risk tasks

- **Risk per task:** T1 medium, T2 medium, T3 medium, T4 high, T42 medium.
- **High-risk tasks:** T4: there is no mutation tool for `sh` (the task's `Mutation` line), so
  mutants of `run.sh` were built by hand in scratch copies: 6 killed, 1 survivor justified as
  equivalent in real use (the fast path also taken for `session_doctor.py`, the skills' scripts or
  near-misses of the recorder's name, whose events carry no `tool_input.command`). One mutant, the
  no-Python gate matching only the first 8 KB, survived until a test was added for it. Three
  security reviews passed. Evidence in `specs/002-efficient-feature-flow/evidence/T4.md`: the real
  gate through `run.sh` denies a commit with the check red, allows it green, and denies it without
  Python.
- **T42 (medium, mutation not required):** 10 hand-made mutants of its code, run against the
  `run.sh` tests in a copy of the plugin: 9 killed. The survivor removes the 64-step budget, which
  changes only the cost: past the budget the event goes to Python (R5.3), without it the same value
  is decided exactly (R5.1).
- **Open risks:**
  - macOS was not run locally. CI runs these tests on macos-latest, where `sh` is bash 3.2; the
    non-ASCII guard's bracket expression and the `dd` reader were run here under Git Bash (bash
    5.3) and in reviewers' runs under dash and `bash --posix`. T42's loop adds `$(( ))` and
    `[ -gt ]`, both POSIX, run here only under Git Bash.
  - Measured the same way, a command that takes the fast path costs 46% less than in 0.6.0 (209
    → 112 ms by median, 209 → 117 ms by mean), just short of the "less than half" in
    requirements.md's Constraints and Final verification step 3. Against the 305 ms quoted from the
    0.6.0 run's transcripts, which also include Claude Code's own cost to start a hook, it is met.
    The Phase 4 diagnosis has to compare like with like and combine the cost with how many commands
    take the fast path.
  - The fast path no longer assumes how the JSON writer spells characters: printable ASCII other
    than `"`, `\` and `/` can only be escaped as `\u`, which sends the event to Python. That guard
    also matches an escaped backslash before a `u` (`\\u`, as in some Windows paths), which costs
    the fast path for about 1% of commands.
  - A 7.5 KB command without quotes takes 140 ms on the fast path, against 113 ms before T42: the
    value cut copies the rest of the event's first 8 KB.
  - `is_other_command` assumes a flat `tool_input`: it takes the first `"command":` after
    `"tool_input":`. That holds for Bash and PowerShell events today; its comment does not say so.
  - Not changed here: without Python, the launcher's rough `*git*commit*` match lets an obfuscated
    command such as `g""it commit` through.
  - On this machine the working copy of `run.sh` is CRLF (`core.autocrlf=true`); the index and the
    commits store LF, and this machine's `sh` runs the CRLF copy.

## Decisions

- How `run.sh` reads the event before deciding (T1): a builtin `read` loop over all stdin |
  `head -c 8192` for the start, a `case` decision and `cat` to drain the rest → **`head -c 8192`,
  `case` and `cat`** (user). After the code review, the reader became `dd bs=8192 count=1` instead
  of `head -c`, keeping the fixed-size start, the `case` decision and the `cat` drain; the spec
  re-review judged it faithful to the choice.
- Whether S1 also decides on quoted commands, after the first summary: leave T1's rule, where any
  JSON escape goes to Python | add T42 to S1, deciding on the escaped text → **add T42** (user,
  2026-10-30: "Sí, agrégala").
- No subagent returned `Status: DECISION` during the build. T42's `\u` guard and 64-step budget
  were the implementer's, inside the task; the spec review did not count the guard as out of scope,
  and the code review kept both.

- **Suggestions not applied:**
  - T1: the property test varies only ASCII spaces between the command's words; it uses the
    private `quality_check._equivalent_forms`; the non-ASCII guard also catches tab, newline and
    CR, so an override with a stray newline quietly loses the fast path.
  - T2: the property test's random draws depend on the temporary path's length (the other
    property tests seed per case instead); no case puts a newline at byte 8192 of a larger event;
    `package.json` writes that `run.sh` never reads.
  - T3: a shared helper for the repeated `subprocess.run` of `run.sh`; `subTest` per case; the
    generators draw only some of the variants their tuples list, and `_far_case` is hard to follow.
  - T4: the no-Python deny at the end of the example test repeats the new past-8 KB test more
    weakly; `SKILL_SCRIPTS` omits `find_duplicates.py`; 5 of the property test's 19 names never get
    an event the recorder would skip; the example test keeps `KONUNDRM_CHECK_CMD`, so an interpreter
    path with a non-ASCII character would disarm it; the past-8 KB test could use a prefix longer
    than a pipe buffer.
  - T42: raise the value cut's budget from 64 to 256 steps (about 0.07 ms each), which would put
    the 204 commands that exhaust it back in reach of the fast path (74.4% → 76.4%); make the `\u`
    guard exact by pairing backslashes before each `u` (51 commands, worth it only if Windows paths
    become common); split `test_run_sh_skips_python_for_a_quoted_command_that_is_not_the_check`,
    which checks three rules, so a failure names the broken one.
