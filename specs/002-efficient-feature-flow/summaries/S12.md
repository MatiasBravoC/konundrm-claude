# Slice S12 summary: version 0.7.0, its changelog and the README of the new flow

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T40–T41

## What changed and why

The feature ships as 0.7.0 (US7, R7.2): `plugin.json` says 0.7.0, so installed copies update, and
the changelog's [0.7.0] entry names each mechanism the feature added: a new session per slice, one
full check per task, parallel reviews, `task_ledger.py`, the fast path of `run.sh`, `run_slices.py`
and `session_costs.py`. Its opening paragraph quotes the 0.6.0 baseline from `requirements.md`
(orchestrators about 57% of the weighted tokens, 290 full checks, about 5.7 h of check) and says
the savings are not measured yet; it lists the new tests the check runs for the feature's
agreements (R7.1), the known limitations still true of the code, and what upgrading needs (T40).
The README now describes the session per entrega and the `- **Sessions:** single` header line,
one check per task with the reviews at once, how to chain the sessions from a terminal with
`run_slices.py`, and how to measure a run with `/konundrm-eng:measure-impact` plus transcript
folders (quoted when they hold spaces) or `session_costs.py`; it also fixes stale lines on the
plugin's tools, the `run.sh` fast path and what the contract tests check (T41). The hook suite went
from 478 to 480 tests (1 skipped on Windows).

## Risks and high-risk tasks

- **Risk per task:** T40 low, T41 low.
- **High-risk tasks:** none.
- **Open risks:**
  - README `## Uso` step 4: it does not say to run `run_slices.py` from the project's root, that
    the headless sessions need permission to edit and run commands (Claude flags after `--`, or
    settings that allow them) or the run ends in `STALLED:` or `FAILED:`, nor that the plan must be
    `Approved` with a base commit; its example puts this repository's plugin path next to a user
    project's `specs/003-google-login`; and step 8's `sh <carpeta del plugin>/hooks/run.sh` does
    not say to quote the folder, although the real `installPath` holds a space on this machine
    (T41's code review).
  - README wording: "sus revisiones de spec, de código y de seguridad corren al mismo tiempo" reads
    as a security review on every task (it runs only on high-risk tasks); the `hooks/run.sh` line
    of the `## Contenido` tree says "sin Python si el comando no puede ser el check", but the fast
    path applies only to the hook that records checks; "Las skills también usan seis herramientas"
    includes `run_slices.py`, which no skill runs (T41's spec and code reviews).
  - CHANGELOG [0.7.0]: a plan that cannot be read at all prints `<path>: cannot read the plan`
    without a line number, not `<file>:<line>` as the entry says (`task_ledger.py`'s docstring has
    the same imprecision; T40's code review).
  - Tests: the version text `".".join(...)` repeats three times in `test_release.py`;
    `_read_markdown_section` is a second Markdown section reader beside
    `plugin_files.read_section`, which could be generalized instead; a `# ` line inside a fenced
    code block would end a section early, making the test fail, never pass (T40's and T41's code
    reviews).
  - Still open from earlier slices: `agents/security-reviewer.md` still says it runs "after the
    code review" (line 3) and that "a code reviewer already judged design and readability" (line
    12), although the reviews now run at once; `test-driven-development` still runs "the suite so
    far" (T40's implementer). The [0.7.0] entry's Known limitations keep S9–S11's open risks
    (chained checks not recorded, the unranged partition lookup, `run_slices.py`'s and
    `session_costs.py`'s limits).

## Decisions

- What version the release test requires in `plugin.json`: 0.7.0 or later, compared as numbers,
  plus a [0.7.0] entry looked up by version | exactly "0.7.0" → **0.7.0 or later** (recommended;
  T40, recorded in `tasks.md`).
- Where the README test looks: the session per entrega and `Sessions: single` in
  `### Cómo avanza una feature`, chaining and measuring in `## Uso` | the whole README → **those
  sections** (recommended; T41, recorded in `tasks.md`).
- What counts as measuring a run: "transcripci" with `session_costs.py` or `measure-impact` |
  `session_costs.py` by name → **either** (recommended; T41, recorded in `tasks.md`).
- `_changelog_mechanism_gaps` takes the version and the mechanism list, so the 0.6.0 and 0.7.0
  tests share it (test-writer, T40); `_read_markdown_section` reads a heading of any level up to
  the next one of the same or a higher level (test-writer, T41).
- The changelog quotes no measured number for 0.7.0 (S1's hook timing and S7's commit timings
  stay out) so it claims no savings before Phase 4's comparison (implementer, T40); the README's
  measuring example uses a made-up Windows path with a space, quoted (implementer, T41).
