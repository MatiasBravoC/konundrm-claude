# Slice S10 summary: `session_costs.py` measures a run's tokens and time per role from its transcripts

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T33–T35

## What changed and why

The plugin's author can now measure a run with data instead of impressions (US6):
`sh "${CLAUDE_PLUGIN_ROOT}/hooks/run.sh" session_costs.py <folder>... [--check-pattern REGEX]` reads
one or more Claude Code transcript folders and prints a table with one row per role (the
orchestrator, whose dispatches are its sessions, and each subagent type from its `meta.json`):
dispatches, turns, input, cache-write, cache-read and output tokens, weighted tokens (weights 1;
1.25; 0.1 and 5), the role's share, its active minutes (median and total, pauses over 5 minutes left
out), its full check runs with their total minutes, its test runs and its messages that dispatched
two or more subagents at once (T33, T34, R6.1). After the table comes the orchestrator session with
the most turns: its turns and the context of its turns, first, median, 90th percentile and maximum
(T35, R6.2). A message written on several lines is one turn and counts the usage of its last line:
T33's code review found that earlier lines can carry a partial `output_tokens`, which undercounted
about 5% of the output tokens on this machine's transcripts. On this project's own transcripts the
command ran in 2 s over 11 sessions and 8 roles. S11 adds never printing content (T36), invalid
lines (T37), long Windows paths (T38) and the impact report (T39).

## Risks and high-risk tasks

- **Risk per task:** T33 low, T34 low, T35 low.
- **High-risk tasks:** none.
- **Open risks:**
  - A `--check-pattern` given by the user is searched anywhere in each simple command's text
    (`re.search`), so an unanchored `npm run check` also counts `grep -n "npm run check" notes.md`
    as a check run; only the default pattern is anchored. Start the pattern with `^` meanwhile
    (T34's code review).
  - The default check keeps only the first simple command of a chained check (with
    `ruff check . && pytest`, every bare `ruff check .` counts as a full check run), and a check
    that is itself a test runner (`pytest`) makes every `pytest -k …` a check run (T34's code
    review).
  - The test-runner list is fixed (`python -m unittest`, `python -m pytest`, `pytest`, `npm test`,
    `npm run test`): `pnpm`/`yarn`/`bun test`, `npx vitest`, `uv run pytest` and `py -m pytest` are
    not counted (T34's code review).
  - A message's usage comes from its last line, which assumes lines are written in streaming order;
    a per-field maximum would not (T33's code re-review). On this machine the last line always held
    the largest `output_tokens` (1,283 of 25,367 multi-line messages differ, only in that field).
  - Lines with no message id collapse into one turn and one dispatch key; a subagent transcript
    without `meta.json` or `agentType`, a line that is not JSON or a bad timestamp stops the report
    with a traceback (T33 and T34 code reviews; T37 covers invalid lines).
  - Transcript paths over 260 characters are not read yet (T38), so the 0.6.0 run's transcripts
    cannot be measured before S11.
  - Untested: an invalid `--check-pattern` exits 2 without printing the pattern (T34's spec
    review); a tie for the busiest session (the first found wins) and a run with no session turns
    (the block is left out).
  - Tidy-ups: `format_role_table`'s docstring still names `collect_role_costs` (renamed
    `collect_run_costs`); `RunCosts.add` counts turns before checking the role (T35's code review);
    the module's section index is misaligned (T34's code review); the one-line `RoleCosts.add`
    docstring and the test's identity `COLUMNS` map (T33's code review).
  - Still open from S7–S9: see `summaries/S9.md`.

## Decisions

- What an orchestrator dispatch is: each session transcript | each `Agent` call → **each session
  transcript** (recommended; T33, recorded in `tasks.md`).
- What the check is without `--check-pattern`: the project's check command as
  `quality_check.find_check_command` finds it from the current folder | a fixed pattern of the usual
  forms → **the project's check command** (recommended; T34, recorded in `tasks.md`).
- How a Bash or PowerShell command line is read: each simple command the commit gate's splitter
  (`shell_commands.iter_commands`) finds | the pattern searched in the whole line → **each simple
  command** (recommended; T34, recorded in `tasks.md`).
- The 90th percentile of context per turn: nearest rank | linear interpolation → **nearest rank**,
  always a real turn's context (recommended; T35, recorded in `tasks.md`).
- Which line's usage counts for a message written on several lines: the first | the last (or the
  largest per field) → **the last** (T33's code review, Critical, confirmed by the orchestrator over
  this machine's transcripts; implementer).
- A role's name: the `meta.json` `agentType` whole, such as `konundrm-eng:test-writer` (test-writer,
  T33).
- A user's `--check-pattern` is searched in each simple command; the default is anchored at its
  start (implementer, T34; see the open risks).
- A tie for the busiest session: the first found wins (implementer, T35).
