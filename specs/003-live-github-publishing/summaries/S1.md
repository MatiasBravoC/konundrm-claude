# Slice S1 summary: commits say only what changed, and the plugin points to its repository

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T1–T6

## What changed and why

The flow's data for each task commit (the task, the requirements it covers and its review rounds)
no longer goes in the commit message: `task_ledger.py message` writes only the subject and body and
leaves those lines in a pending note, and the new `task_ledger.py record` attaches the note to the
commit under `refs/notes/konundrm`. The task reader and the impact report read the message and the
note, so features 001 and 002 (lines in the message) and mixed histories keep working. The skills
that make commits (develop-feature, committing-changes, fix-bug) and those that search them
(opening-pull-requests, reviewing-pull-requests) follow the new flow, and the plugin's manifest,
README and setup-project templates now point to `MatiasBravoC/konundrm-claude`. This answers the
user's ask that a commit speak only about its change, since another developer does not know the
workflow (R6.1–R6.5), and fixes the addresses (R8.1, R8.2).

## Size

1,065 changed lines of code and tests (884 added, 181 removed) against a budget of 500 per slice,
over by 565, plus 478 lines of the feature's documents (spec and plan). Most of it is T5: the skill
text of six skills, four eval graders and a 258-line contract test, plus the property tests that
T1 and T3 needed as medium-risk tasks.

## Risks and high-risk tasks

- **Risk per task:** T1 medium, T2 low, T3 medium, T4 medium, T5 medium, T6 low
- **High-risk tasks:** none
- **Open risks:** suggestions not applied, all non-blocking: `record` would accept a blank pending
  note and report success (`task_ledger.py:369-374`), and an `OSError` on deleting the second
  pending file would show a traceback (`:372-373`); `message` writes the message before the note,
  so a failed second write could leave a stale note (`task_ledger.py:193-194`); on a resumed
  parallel wave, develop-feature pairs notes against `<fork-point>..<branch>` while the pick is
  `<last>..<branch>`, so a note could be copied to the wrong commit (`develop-feature/SKILL.md:376-377`);
  the README says a project's CI needs a token for the private repository but not how to give it.

## Decisions

- Scope of the feature: 47 tasks in 12 slices | 15 tasks | 10 tasks that address only the request → **10 tasks** (user)
- Where the flow's data lives: in the commit message | in a Git note outside it → **Git note under `refs/notes/konundrm`** (user asked that commits speak only of the change; the design chose notes over a JSON file of its own)
- T5's files: the five skills planned | also engineering-standards §6, measure-impact and the eval graders that pinned the old lines → **also those files** (orchestrator, same rule)
- T7's files: also `measure-impact/SKILL.md` and the README, which still say the budget is 400 (orchestrator, from T2's code review)
