# Slice S9 summary: polish after the reviews, with a sturdier tasks.md reader, a wave-aware session start, PowerShell-safe stash recovery and tighter contract tests

## What changed and why

S9 applies the review suggestions from earlier slices that were worth keeping. It adds no new mechanism; it closes gaps the reviewers found in S1–S8's work. The main session added the slice during the run, under the user's permission to decide and request to be maximalist. Its tasks come from three sources, each recorded in an HTML comment under the slice heading:
- **T60–T69:** code-review suggestions on earlier tasks (plan change 99ddad8).
- **T71 and T72:** the T29 and T27 reviews (plan change 9acda84).
- **T73–T76:** the side sessions' review notes on T61, T63, T66 and T68 (plan change d5981a1).

All three plan changes come before this slice's range (`0e6570f..bd72d9f`).

What changes, by area:
- **The tasks.md reader** (`hooks/scripts/tasks_document.py`):
  - A partition cell's explicit IDs now match by number, so `T01` lists task `T1`, as ranges already did (R3.8, T61).
  - An unfilled `- **Parallel:**` line, or one whose options sit only in a comment, reads as serial. Only a whole value of `yes` on the label's own line reads as parallel (R3.6, T62).
  - A task number longer than 18 significant digits matches nothing, instead of hitting CPython's 4300-digit `int` limit and crashing the reader (R3.8, T73).
  - Each task now carries the Wave of its partition row (T74).
- **The session start** (`hooks/scripts/session_doctor.py`) lists only the partitions of the wave in progress, so wave 2 waits until wave 1 is done (R3.7, T74). Two existing behaviors are now pinned by a test: partitions in numeric order (P2 before P10), and a single next task outside a parallel wave (T63).
- **develop-feature and fix-bug:**
  - A set-aside attempt is recovered by looking its stash entry up by message and applying it by SHA (`git stash list --grep="<message>" --format=%H`, then `git stash apply <sha>`). Positions shift, worktrees share one stash list, and PowerShell breaks an unquoted `stash@{n}` (R8.2, T66 then T75).
  - fix-bug runs every test-writer and implementer dispatch after a rethink on Opus at high (R1.2, T67).
  - A resumed run whose last slice has every task committed but no `summarize slice S<k>` commit runs that Slice checkpoint first (R4.1, R6.1, T71).
  - Model and effort drops a result nothing backs, and no longer contradicts its own table about first attempts (T68, T76).
- **The CI review template:** it now says `--model` and `--effort` set only the session running the review skill (R1.7, T69).
- **Tests:**
  - The huge-range test times only the read (T60).
  - The rethinker test reads verdicts from the `Verdict:` line only and counts MultiEdit as a writing tool (R8.1, T64).
  - The read-only roles test confirms the role name before the denial (R8.5, T65).
  - A meta test fails when a contract test module binds one module-level name twice, the silent overwrite that weakened T19's rule during T27 (R10.2, T72).
