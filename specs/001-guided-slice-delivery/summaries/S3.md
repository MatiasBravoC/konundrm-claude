# Slice S3 summary: plans split each slice into partitions and waves, and the reader understands them

- **Spec:** [requirements.md](../requirements.md) · **Design:** [design.md](../design.md) · **Tasks:** [tasks.md](../tasks.md)
- **Tasks:** T11–T18, T55 (plus plan change a0db71d, which added T55–T59)

## What changed and why

writing-plans now closes each slice with a `### Partitions` table of waves (at most three partitions per wave, no shared files or dependencies inside a wave, IDs unique across the feature), and its tasks.md template carries those tables plus the `Parallel:` and `Checkpoints:` header lines (R2.1, R3.1, R4.5). The tasks.md reader assigns each task to the partition of the first row that lists it, accepts ranges such as `T1–T3` with any of the agreed separators and bold cells, and reads the `Parallel:` line (R3.1, R3.6, R3.8); T55 keeps a range as its bounds, so `T1–T10000000000` no longer hangs the session start (R3.8). The session-start hook names each partition's next task while partitions run in parallel (R3.7), and develop-feature and opening-pull-requests find a task's commit with the anchored `-E --grep '^Task: T<n>( |$)'`, so T1 never matches T10 (R9.1).
