## What changed and why

A new meta test, `hooks/tests/contract/test_meta.py`, reads every contract test module and fails when a test would not run under unittest discovery or when the first line of its docstring does not start with the requirement IDs it protects (`R1.7: ...`). unittest prints that line after `FAIL:`, so a broken contract test now names the broken agreement in the check's output (R10.2, T51). The plugin also gains five behavior evals under `evals/`, one per new mechanism the user meets: the slice checkpoint with its questions, the design decision at plan approval, the slice summary, the feature summary and the improvement notes. Each runs develop-feature on a tiny project with `claude plugin eval`, outside the check; a contract test in `test_release.py` checks only their structure, a `prompt.md` with a frontmatter and a prompt plus at least one grader with a documented `type:` (R10.3, T52).

How it was built: T51 and T52 in the parallel "templates" session (branch `claude/p-templates-evals-788653`). T51 passed on arrival (CHARACTERIZATION): every existing contract test already complied, so there was no green step. The main session integrated both by cherry-pick, running the full check before each commit: T51 efc8006 → 32fe929, T52 91cfb78 → 129eceb.

Plan change (80f61db, inside this slice's range): T53 (version 0.6.0 and changelog) and T54 (README) move from S8 to a new last slice S10, so S9 can be integrated while they are written and the changelog also covers S9. S8 is renamed "suite y evaluaciones" and design.md's Delivery paragraph now lists ten slices.

## Risks and high-risk tasks

- **Risk per task:** T51 low, T52 low
- **High-risk tasks:** none (no mutation run required)
- **Open risks:**
  - **The evals have never been run.** The check only verifies their structure. The templates session recommends reviewing them before running them, because of the grader problems below (session handover notes).
  - **T52 suggestions not applied:**
    - `behavior-improvement-notes/graders/{notes-not-written-by-hand,plugin-not-edited,plugin-not-rewritten}.md`: `input_match` scans the whole tool input JSON, content included, so a correct run can fail; it should be anchored to `"file_path"`. Writes and edits done through Bash (`cat >> …improvements.md`, `sed -i`) are not graded.
    - `behavior-improvement-notes/graders/notes-are-clean.md` (`focus: trace`): the judge sees only the first and last 12 messages, so the process-reviewer's last report can fall outside; it should be told to use the notes of the last `improvement_notes.py` call.
    - `behavior-design-decision/graders/no-code-before-choice.md`: `**/*.py` fails if the setup creates a `.py` (for example `uv init` creates `main.py`); `**/*duracion*.py` would not.
    - `behavior-design-decision/prompt.md`: the sentence "esa elección quiero tomarla yo" lets `options-at-plan-approval` pass even if the plan does not spot the decision on its own; it should be dropped, leaving the two approaches named.
    - `summary-committed.md` and `summary-commit.md`: they require a scope (the design fixes `docs(<scope>)`) and miss a commit made with `git commit -F <file>`.
    - `behavior-slice-checkpoint/graders/checkpoints-ask.md`: accepts the unfilled placeholder `ask | pre-approved`; adding `(?!\s*\|)` fixes it.
    - `behavior-feature-summary/graders/slice-summaries-written.md`: checks only `S2.md`, although its text speaks of every slice.
    - `test_release.py` does not check unknown frontmatter keys or the limits (`max_turns` ≤ 200, `timeout_seconds` ≤ 3600), although its docstring says the case can run; it also re-parses the `---` fences after `read_frontmatter` (a `read_body` in `plugin_files.py` would avoid it).
    - For T54: the README's evals section lists which `behavior-*` cases need subagents, git and `--ablation none`; the five new ones need all three but match none of its name patterns.
  - **T51 suggestions not applied:**
    - `test_meta.py:27-33`: `_is_test_case` recognizes only `TestCase` or subclasses from the same module, so a shared base imported from another module would get the wrong message ("discovery does not run it").
    - `test_meta.py:53`: `ast.walk` is breadth-first, so gaps come out by depth, not in source order; they should be sorted by `lineno`.
  - **The checkpoint ran pre-approved:** S8's summary is committed at the slice's end, and the process-reviewer's notes for S8 are saved after that commit, so they are not described here.
